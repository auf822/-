# 实现设计与需求解释

## 结构

```text
浏览器（中文响应式 SPA）
  └─ 同源 Cookie + CSRF 校验 → FastAPI
       ├─ 角色与授权检查
       ├─ 学年 / 志愿 / 配对 / 名额 / 审核 / 通知
       ├─ Excel 校验与导出
       └─ SQLite（WAL、外键、写事务、归档快照、追加日志）
```

服务端采用 Python 3.12 和 FastAPI；数据库采用 SQLite 3。浏览器为 Chrome、Edge、Firefox 等现代浏览器。页面不向外部 CDN 请求资源，启动无需前端构建。

`app/db.py` 保存结构、密码算法与审计，`app/business.py` 保存业务不变量，`app/main.py` 暴露 API，`app/static/` 为页面。数据库首次启动只创建结构，不自动创建账号；示例数据通过显式命令生成。

## 核心数据

- `users`：账号、角色、岗位授权、专业、成绩和学生所属学年。导师不绑定年度。
- `years`：学年、状态、志愿上限、两轮时间窗口、专业总额和结果审核状态。
- `profiles` / `profile_requests`：已发布资料和独立审核版本；新提交使旧待审核版本失效。
- `quotas`：导师年度名额，不存储易漂移的“剩余人数”。
- `applications`：每轮志愿、顺序、审核状态、时间与原因。拒绝/撤回不占有效志愿数量。
- `matches`：同一学年学生唯一匹配。事务中检查导师容量。
- `round2_eligible`：首轮截止时未匹配学生快照。之后解除首轮配对不自动获得二轮资格。
- `year_snapshots`：归档时冻结配对明细、全套报表和管理统计；导师跨年改名不会改写历史成果。
- `sessions`：服务端保存令牌哈希、CSRF 令牌和过期时间。明文 Cookie 不落入日志。
- `notifications`：仅本人可查看和标记已读。
- `audit`：追加审计记录、前序哈希和本条哈希。密码、会话 Cookie 和导入初始密码不入日志。

## 业务不变量

1. 剩余名额 = 年度上限 − 已配对人数，不允许负数。
2. 志愿提交不占用招生名额，导师确认立即配对并消耗一个名额。
3. 学生拥有至多一个本学年匹配，接收后其他待审核志愿自动失效。
4. 每轮只在开启状态和配置时间窗口内接受新增、编辑、撤回与导师审核。
5. 名额耗尽时拒绝提交及接收；名额为零时学生端完全过滤该导师。
6. 学生 API DTO 不包含导师上限、已录取人数或剩余人数，不能依靠隐藏 HTML 实现保密。
7. 拒绝后的志愿只保留历史，不占志愿上限，学生可在本轮重新填报。
8. 二轮不开自动通道，只能在首轮结束后由辅导员一次开启。
9. 调剂失败会回滚，包括原配对删除和名额修改；批量调剂同样整批提交或回滚。
10. 归档需要先审核最终结果；归档前修改相关数据会使结果审核失效。

所有写事务使用 `BEGIN IMMEDIATE`，避免“先读容量、并发写入”导致超招。学生唯一匹配和同导师重复待审核志愿还有数据库唯一索引保护。到期动作在定时线程和接口请求路径中同步触发，仅执行一次并通知师生。

## 原需求中的冲突与采用规则

| 原文冲突 | 实现规则 |
| --- | --- |
| 四级权限但列出五类角色 | 使用五类角色；两种管理岗位职责独立 |
| 学生填报触发名额更新、预录取与确认混用 | 填报只增加意向；确认即正式配对；没有未定义的中间预录取状态 |
| 导师可以取消录取，但又禁止解除生效配对 | 导师仅确认/拒绝待审核意向；生效后仅辅导员可特殊处理 |
| 科研秘书管理名额，辅导员也能调整名额 | 科研秘书负责准备与首轮，辅导员负责首轮后的微调 |
| 学生“无数据修改权限”但允许志愿修改 | 允许未审核且本轮未截止的本人志愿编辑；不允许改基础信息或结果 |
| 全局管理员最高权限但配对解除辅导员唯一 | 将生效配对解除/调剂保留为辅导员专属能力 |
| 智能匹配与方向相近没有数据或评分定义 | 仅提供同专业、成绩、已有志愿和容量的确定性建议，由辅导员预览确认，不声称语义匹配 |

## 导入与导出

导入仅接受标准 `.xlsx`，请求上限5MB，解压内容上限20MB、200个 ZIP 项目、2000行；拒绝公式、重复工号/学号、错误基础信息、非法名额和低于已录取人数的名额。校验失败返回行号且不写入任何行。

师生导入只新增，不隐式覆盖已有账号；导师名额导入按既有工号更新。学生初始密码不在返回值或审计中回显。标准模板第一列应设置为文本，避免 Excel 吞掉学号的前导零。

导出提供师生配对总表、分专业工作表、导师招生汇总、未匹配学生表、名额填报名单与导师本人录取明细。文本以 `= + - @` 开头时加文本前缀，防止公式注入。归档学年使用冻结报表。

## 安全边界

密码使用随机盐 scrypt；Cookie 为 HttpOnly、SameSite=Strict，所有已登录写操作校验 CSRF，额外校验浏览器 Origin。限制单账号/来源的失败登录次数，禁用账号及密码重置会撤销会话。页面转义用户文本，API 不暴露密码哈希，Excel 导出防公式注入。

当前版本未接入学校统一认证、邮件/短信网关或外部审计留存，这些需实际接入配置。部署为公网服务需要 HTTPS、学院授权的数据保存策略与备份管理；高并发、多实例运行需要升级数据库和集中调度。
